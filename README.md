# Школьные опросы

Веб-приложение для проведения опросов среди учащихся школы. Без внешних зависимостей:
сервер на встроенном модуле Node.js `http`, база данных — встроенный `node:sqlite`,
экспорт в Excel/PDF — собственные генераторы. Один процесс, один файл БД — легко
развернуть и обслуживать.

## Возможности

- **Личный кабинет администратора** с единым паролем (смена пароля в интерфейсе).
- **Роль «редактор»**: отдельный пароль, доступ к опросам/классам/отчётам без права
  менять пароль и настройки (настраивается в разделе «Настройки»). Персональные
  данные участников (ФИО) доступны только администратору.
- **Дашборд «Обзор»**: активные опросы, ответы за неделю, активность за 14 дней.
- **Создание опросов**: вопросы четырёх типов — одиночный выбор, множественный
  выбор, **шкала (оценка 1–5 или 1–10)**, свободный текст.
- **Редактор**: изменение порядка вопросов и вариантов кнопками ↑/↓,
  автосохранение черновика каждые 30 секунд, предупреждение при уходе
  с несохранёнными изменениями, **предпросмотр глазами ученика**.
- **Сохранение черновика без блокировки** + проверка заполнения при публикации.
- **Расписание публикации**: даты открытия и закрытия, сообщение «опрос завершён»,
  дата публикации и история публикаций, индикатор «закроется через N дней».
- **Ручная публикация/снятие** опроса кнопкой, **копирование** и удаление опроса.
- **QR-код и короткая ссылка** `/s/:id` для каждого опроса — выводится на проектор
  или печатается; генерируется встроенным генератором без зависимостей.
- **Управление списком классов**: массовое добавление («9А, 9Б, 10А» одной строкой),
  инлайн-переименование, счётчик ответов, естественная сортировка (9А, 9Б, 10А, 11В).
- **Обязательная авторизация участника**: имя, фамилия, класс. Без заполнения данных
  к опросу не пускает и выводит сообщение о необходимости внести данные.
- **Прохождение опроса один раз** (см. раздел «Защита от повторов»).
- **Полноэкранный режим прохождения** с прогресс-баром (по одному вопросу на экран);
  ответы переживают случайное обновление страницы (sessionStorage).
- **Сохранение ответов** в SQLite (имя, фамилия, класс, опрос, ответы, IP, дата).
- **Отчёты**: сводка по каждому вопросу (количество, проценты, средние оценки),
  разбивка по классам со сравнительными диаграммами, «ответы по дням»,
  индивидуальные ответы с поиском и пагинацией, история публикаций,
  вкладка «Участники» с ФИО (только администратору),
  выгрузка в **Excel (.xlsx)** и **PDF** (с поддержкой кириллицы).
- **Брендинг**: логотип, фото и название школы — всё меняется в настройках
  (файлы обрабатываются в браузере и загружаются без перезапуска сервера).
- **Защита от перебора пароля** хранится в БД и переживает перезапуск.
- **Тёмная тема** (по системной настройке), стили печати отчётов.
- **Адаптивная вёрстка** для смартфонов.

## Требования

- Node.js **22.5+** (используется встроенный модуль `node:sqlite`). Рекомендуется
  Node.js 22 LTS или новее. Проверено на Node.js 26.

## Быстрый запуск (локально)

```bash
# Windows / macOS / Linux
node server.js
```

Откройте <http://localhost:3000>.

**Пароль администратора по умолчанию: `admin123`** — обязательно смените его после
первого входа: раздел «Настройки». Пароль хранится в БД в виде хэша (scrypt).

## Запуск в Docker

Сборка и запуск через docker compose:

```bash
docker compose up -d --build
```

Или вручную:

```bash
docker build -t school-survey .
docker run -d --name school-survey \
  -p 3000:3000 \
  -v school-survey-data:/app/data \
  -e ADMIN_PASSWORD=смените_на_свой \
  school-survey
```

- База данных (`app.db`) хранится в volume `school-survey-data` — данные переживают
  пересоздание контейнера.
- `ADMIN_PASSWORD` задаёт пароль **только при первом запуске** (пока БД пуста);
  далее пароль меняется в разделе «Настройки».
- За обратным прокси (nginx) добавьте `-e TRUST_PROXY=1`, чтобы корректно определять
  IP участников.
- Файл `fonts/DejaVuSans.ttf` уже внутри образа — PDF-экспорт работает без внешних шрифтов.

### Первые шаги

1. Войдите в админку (ссылка «Вход для администратора» на главной).
2. В разделе «Классы» добавьте классы (например, `9А`, `10Б`).
3. Создайте опрос, добавьте вопросы и варианты ответов.
4. Нажмите «Опубликовать».
5. Раздайте ученикам ссылку на главную страницу (или прямую ссылку на опрос).

## Настройки (переменные окружения)

| Переменная        | По умолчанию   | Описание |
|-------------------|----------------|----------|
| `PORT`            | `3000`         | Порт сервера |
| `HOST`            | `0.0.0.0`      | Адрес прослушивания |
| `ADMIN_PASSWORD`  | `admin123`     | Пароль администратора при первом запуске |
| `SURVEY_DB`       | `data/app.db`  | Путь к файлу базы данных SQLite |
| `TRUST_PROXY`     | `0`            | `1` — доверять заголовкам `X-Forwarded-For` (за nginx) |
| `ENFORCE_IP`      | `0`            | `1` — дополнительно блокировать повтор с одного IP |
| `FONT_PATH`       | `fonts/DejaVuSans.ttf` | Шрифт для PDF (нужна кириллица) |

## Защита от повторного прохождения

Работают три уровня (требование «один ученик — один раз»):

1. **Уникальность «имя + фамилия + класс»** для каждого опроса — включена всегда.
   Повторная отправка с теми же данными отклоняется (ошибка «Вы уже проходили…»).
2. **Cookie** — после отправки в браузере ставится отметка; с этого устройства
   повторно пройти опрос нельзя.
3. **IP** (опционально, `ENFORCE_IP=1`) — блокирует повторную отправку с одного
   IP-адреса.

> **Важно про IP.** В школе ученики часто выходят в интернет через один общий
> NAT-адрес. Поэтому блокировка по IP по умолчанию **выключена** — иначе после первого
> ученика весь класс не смог бы ответить. Включайте `ENFORCE_IP=1`, только если уверены,
> что каждый участник имеет отдельный IP.

## Развёртывание на сервере (Docker + nginx + HTTPS)

Готовый сценарий [`deploy.sh`](deploy.sh) разворачивает всё одной командой на Ubuntu
(Docker должен быть уже установлен): собирает контейнер, настраивает nginx как
обратный прокси и получает HTTPS-сертификат Let's Encrypt.

1. **Склонируйте репозиторий** (он приватный — нужен токен или GitHub CLI):

   ```bash
   # вариант A: через GitHub CLI
   gh auth login && gh repo clone aleksej308/school-survey

   # вариант B: через персональный токен (classic «repo», либо fine-grained «Contents: read»)
   git clone https://<ТОКЕН>@github.com/aleksej308/school-survey.git
   cd school-survey
   ```

2. **Запустите развёртывание** (от root; скрипт спросит пароль администратора):

   ```bash
   sudo bash deploy.sh опросы.ваша-школа.рф admin@ваша-школа.рф
   ```

   После завершения приложение доступно по адресу `https://опросы.ваша-школа.рф`.
   Пароль администратора можно передать и сразу: `sudo ADMIN_PASSWORD='...' bash deploy.sh ...`.

3. **Обновление** (при выходе новой версии):

   ```bash
   git pull
   sudo bash deploy.sh опросы.ваша-школа.рф admin@ваша-школа.рф
   ```

Перед запуском убедитесь, что в файрволе/облаке открыты порты **80** и **443**
(скрипт сам откроет их в `ufw`, если тот активен). Данные БД хранятся в volume
`school-survey_survey-data` и сохраняются при пересоздании контейнера.

### Несколько независимых инстансов на одном сервере

Каждому инстансу — свой домен, своя база и свой контейнер. Имя инстанса задаётся
переменной `STACK` (по умолчанию `school-survey`, поэтому существующая установка
обновляется без изменений):

```bash
sudo STACK=vika-opros bash deploy.sh vika-opros.domen.ru admin@domen.ru
```

У такого инстанса: контейнер и образ `vika-opros`, volume с БД `vika-opros_survey-data`,
отдельный nginx-конфиг `/etc/nginx/sites-available/vika-opros` и свой порт
(запоминается в `/etc/school-survey-ports/vika-opros`, чтобы не менялся между запусками).
Обновление конкретного инстанса — с тем же `STACK`:

```bash
git pull && sudo STACK=vika-opros bash deploy.sh vika-opros.domen.ru admin@domen.ru
```

## Резервное копирование

Все данные хранятся в одном файле — `data/app.db`. Для резервной копии достаточно
скопировать этот файл (лучше при остановленном сервисе или использовать
`sqlite3 data/app.db ".backup backup.db"`).

## Структура проекта

```
server.js              — HTTP-сервер и все маршруты (API)
lib/db.js              — слой БД SQLite (схема и запросы)
lib/auth.js            — scrypt-хэши паролей и HMAC-сессии
lib/xlsx.js            — генератор .xlsx (без зависимостей)
lib/pdf.js             — генератор .pdf с кириллицей (встраивает шрифт)
public/                — фронтенд (SPA): index.html, css, js
public/js/qrcode.js    — генератор QR-кодов (без зависимостей)
fonts/DejaVuSans.ttf   — шрифт для PDF (лицензия OFL)
data/app.db            — база данных (создаётся при первом запуске)
Dockerfile             — образ приложения (TZ=Europe/Moscow)
docker-compose.yml     — сборка и запуск контейнера
deploy.sh              — развёртывание на сервере (nginx + HTTPS)
scripts/               — вспомогательные скрипты и тесты
```
